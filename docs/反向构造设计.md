# Queen 消元解谜 — 反向构造生成器设计

## 1. 为什么需要反向构造

正向构造的根本问题：生成器和 solver 是两套独立系统。生成器按策略序列放置格子，solver 独立在棋盘上寻找模式。两者之间没有强制对应。

反向构造：**把 solver 的求解过程倒过来执行，从终态还原到初态**。每一步反向操作精确对应 solver 正向的一步。

## 2. 核心概念

```
正向求解：全活 → L2_Lock1消除 → L1确认+传播 → ... → 全Queen确认+其余X
反向构造：全Queen确认+其余X → 取消L1的传播 → 取消L2_Lock1的消除 → ... → 全活
```

### 状态空间差异

| 概念 | 正向构造 | 反向构造 |
|------|---------|---------|
| 初始状态 | 全未着色 | 全 Queen 确认 + 其余全 X |
| 最终状态 | 全着色 | 全活（无 X） |
| Step 操作 | 着色新格 + 标记约束/X传播 | 取消 X + 分配 region |
| 约束系统 | 显式前约束属性 | X/活 状态直接体现 |
| Solver 一致性 | 不保证 | **保证**（棋盘按求解轨迹反向构建） |

## 3. 数据结构

```
ReverseBoard:
  region[r][c]: 每格归属（-1 未分配）
  isX[r][c]: 是否 X
  isQueen[r][c]: 是否已确认 Queen
```

初始状态：n 个 solution 格 isQueen=true，其余 isX=true。

## 4. 反向策略

### 4.1 反向 L1

取消 Queen 确认 + 取消 X 传播（同行/同列/邻域恢复活格）。活格分配 region：同行/同列 → 不能是本 Queen 的 region。

### 4.2 反向 L2_Lock1（region→row）

在 lockRow 中取消 Lock1 的消除——恢复被标 X 的外来候选格。活格分配为非本 region。

### 4.3 反向 L2_Lock2

两个 region 的两行中恢复外来候选。活格分配为非 A 非 B。

### 4.4 反向 L3

Projection：取消交集格 X。Contradiction：取消矛盾格 X。

## 5. Region 分配统一规则

对每个恢复的活格 (r,c)：

```
禁止 = { Queen_in_row_r 的 region, Queen_in_col_c 的 region }
允许 = {0..n-1} - 禁止 - 额外禁止
随机选一个允许的 region
```

策略特定额外禁止：L2_Lock1 加锁 region，L2_Lock2 加两个锁 region。

## 6. 主流程

1. 生成 n 个合法 solution
2. 初始化：Queen 确认 + 其余 X
3. 反向遍历策略序列（N-1 → 0）：
   - 按策略取消 X → 分配 region
4. 兜底：剩余 X → 恢复活格 → 分配 region
5. Solver 正向验证

## 7. 与正向构造的对比

| 维度 | 正向 | 反向 |
|------|------|------|
| 处理顺序 | 0→N | N→0 |
| 依赖构建 | 显式计算前约束∩前序X传播 | 后续反向步骤自然与前序重叠 |
| 约束表达 | 前约束属性标记 | X/活状态+region分配规则 |
| Solver一致性 | 尽力而为 | 结构保证 |

## 8. 已知限制

反向构造不改变 solver 的 findUniqueCandidates 行为。全活初始棋盘上 L1 不触发，仍需 L2/L3 先 bootstrap。活格的 region 分配有随机性。

## 9. 与 reverse-generation-redesign.md 的关系

本设计在「格子操作」抽象层。`reverse-generation-redesign.md` 在「求解器状态」抽象层（消除依赖图 + 约束化填充 + 消除感知放置）。后者是更完整的方案，本设计可视为其简化子集。
